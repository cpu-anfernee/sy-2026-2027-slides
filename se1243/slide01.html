Part II: Chapter 1 — Building Your First Game Application

Why Learn C# & OOP Through Games?

Textbook Chapter 1 introduces the dual mission of Learning C# by Programming Games:

  • Engaging Practice: Building interactive games can be just as fun as playing them—and gives immediate visual feedback when your code works (or breaks!).
  • Real-World Software Paradigm: Games are natural ecosystems of interacting objects (cannons, paint cans, grids, UI buttons), making them ideal for mastering Object-Oriented Programming (OOP).
  • Transferable Engineering Skills: The architecture, state management, and C# skills you learn apply directly to desktop, web, enterprise, and mobile software engineering.

Chapter 1 Learning Objectives

Before building full games, we transform your workstation into a C# game development environment:

  1. Install Microsoft Visual Studio and the MonoGame framework in the proper sequence.
  2. Create, compile, and execute your first C# game project (Game1).
  3. Navigate Solution Explorer and modify your first line of C# rendering code in Game1.cs.
  4. Understand how Visual Studio organizes Projects and Solutions, and run companion example games (Painter).

1.1 Getting and Installing the Tools

Two core, freely available software tools power our development workflow:

  • Microsoft Visual Studio (IDE): Our Integrated Development Environment for writing C# code, inspecting project trees, auto-completing APIs, compiling, and debugging.
  • MonoGame Framework: An open-source C# framework that handles cross-platform window creation, real-time game loops, 2D/3D graphics rendering, audio, and input devices.
  • Cost & Licensing: Both Visual Studio Community Edition and MonoGame are 100% free for students and independent developers.

Crucial Rule: Installation Order Matters!

Follow this exact sequence when setting up your personal laptop or workstation:

  1. Step 1 — Install Visual Studio FIRST: Install Visual Studio with the .NET desktop development workload enabled.
  2. Step 2 — Install MonoGame SECOND: Install MonoGame templates/extensions after Visual Studio is already installed so MonoGame can register its project templates inside the IDE.

Lab Tooling Note: While the textbook figures show Visual Studio 2017 & MonoGame 3.6, our laboratory uses Visual Studio 2022 & MonoGame 3.8+ templates. All C# code and architectural concepts in the book work seamlessly!

Exploring the Visual Studio Environment

When you launch Visual Studio (Fig. 1.1 in the textbook), four key areas greet you:

  • Get Started / Recent: Quick links to tutorials and recently opened projects/solutions.
  • Open: Open an existing local project/solution (.sln) or clone from a Git/remote repository.
  • New Project: Search and select templates (such as MonoGame Windows Project or Cross-Platform Desktop Project).
  • Solution Explorer (Right Panel): Displays the hierarchical tree of solutions, projects, dependencies, and source files once a project is loaded.

1.2 Creating Your First Game Application

A project is the basic working environment for building a single game or application. Follow these steps to create one:

  1. Launch Microsoft Visual Studio.
  2. In the top menu, select File → New → Project (or click Create a new project).
  3. Filter or select the MonoGame category under Visual C#.
  4. Select the MonoGame Windows Project template (for Windows desktop using DirectX; or Cross-Platform Desktop).
  5. Enter a project Name (e.g., Game1), disk Location, and Solution name, then click OK / Create.

Understanding New Project Settings

When configuring your project in the New Project dialog (Fig. 1.2), pay attention to three fields:

  • Name (Game1): Defines the project folder name, compiled executable name, and default C# namespace.
  • Location: Choose a clean, organized directory path (e.g., C:\SE1243\Labs\) so you can easily locate and zip your work for submission.
  • Solution Name (Game1): Names the outer .sln container file. Keeping "Create directory for solution" checked keeps multi-project workspaces tidy.

1.3 Compiling & Running Your Game

Once Visual Studio generates the template project, test your setup immediately:

  • How to Run: Click the green Start ("play") button in the top toolbar, or press the F5 shortcut key.
  • Compilation Process: Visual Studio compiles your C# files into intermediate language, links MonoGame libraries, and launches the game window.
  • Expected Result (Fig. 1.3): A desktop window titled Game1 filled with a solid Cornflower Blue background!

Even though you can only see a solid color right now, a full real-time game loop is actively running at 60 frames per second!

1.4 Anatomy of a MonoGame Project

Close the game window and inspect the file hierarchy inside Solution Explorer (Fig. 1.4):

  • Solution 'Game1' (1 project): Top-level container organizing your project(s).
  • Game1 (in boldface): Your active game project node.
  • Properties & References: Assembly metadata, target framework settings, and external libraries (MonoGame.Framework).
  • Content: Holds game assets (sprites, sound effects, fonts) managed by the MonoGame Content Pipeline.
  • Program.cs: Contains the C# Main() entry point that instantiates and starts the game.
  • Game1.cs: The core game class containing initialization, update logic, and rendering code.

Inspecting Game1.cs: The Draw Method

Double-click Game1.cs in Solution Explorer and scroll near the bottom to locate the Draw method:

/// <summary>
/// This is called when the game should draw itself.
/// </summary>
/// <param name="gameTime">Provides a snapshot of timing values.</param>
protected override void Draw(GameTime gameTime)
{
    GraphicsDevice.Clear(Color.CornflowerBlue);

    // TODO: Add your drawing code here

    base.Draw(gameTime);
}

GraphicsDevice.Clear(...) wipes the screen every frame and fills it with the specified Color.

Making Your First Code Modification

Replace Color.CornflowerBlue with Color.Chocolate inside Draw:

protected override void Draw(GameTime gameTime)
{
    GraphicsDevice.Clear(Color.Chocolate);

    // TODO: Add your drawing code here

    base.Draw(gameTime);
}
  • Press F5 (or click the green Start button) to recompile and run.
  • Your game window now renders with a warm Chocolate background!

Discovering Visual Studio IntelliSense

How do you know what other color names exist besides CornflowerBlue and Chocolate?

  • Triggering Auto-Complete (Fig. 1.5): Delete .Chocolate and type a dot (.) immediately after Color inside GraphicsDevice.Clear(Color.);.
  • Live Member List: Visual Studio pops up an alphabetical list of every predefined color (AliceBlue, AntiqueWhite, Aqua, Olive, Black, etc.).
  • Rich Tooltips: Highlighting any item displays its C# type signature and exact RGBA values (e.g., R:240, G:248, B:255, A:255).
  • Developer Superpower: IntelliSense works across all C# classes, structs, and MonoGame APIs—eliminating guesswork and syntax typos!

1.5 Projects vs. Solutions

Visual Studio organizes code using a two-tier hierarchy:

  • Project (.csproj): Represents a single game, executable program, or code library you are developing.
  • Solution (.sln): A workspace container that groups one or more related projects together under one roof.
  • Flexible Organization: When creating a new project, you can either generate a brand-new solution or add the new project into your currently open solution.

Why Put Multiple Projects in One Solution?

The textbook's companion code uses one solution per chapter containing multiple projects:

  • Side-by-Side Comparison: Easily open, compare, and copy logic between incremental versions of a game (e.g., Painter1, Painter2, PainterFinal).
  • Shared Workspace: Switch between small concept demos and main game projects without launching multiple Visual Studio instances.
  • Unified Visibility: Every project inside the active solution appears neatly listed in Solution Explorer.

1.6 Running the Textbook's Example Projects

Every chapter in Learning C# by Programming Games includes downloadable sample solutions:

  1. Download and extract the companion source code archive from the book's website.
  2. Navigate to a chapter folder (e.g., 05_ShowingPlayer) and double-click its solution file (ShowingPlayer.sln).
  3. Visual Studio opens the solution and displays all sample projects for that chapter inside Solution Explorer.

Selecting the Startup Project

When a solution holds multiple projects, how does Visual Studio know which one to run when you press F5?

  • The Boldface Rule: The single project displayed in boldface in Solution Explorer is the Startup Project.
  • How to Switch Projects:
    1. Right-click the desired project name in Solution Explorer (e.g., Balloon2).
    2. Click Set as StartUp Project from the context menu.
    3. Press F5 to build and run that specific project!
  • Verification Test: Running Balloon2 displays a window where a balloon sprite smoothly tracks your mouse pointer.

Previewing Our First Full Game: Painter

  • Aiming & Shooting: Move the mouse to rotate the paint cannon in the bottom-left corner; left-click to shoot paint balls.
  • Color Switching: Press R (Red), G (Green), or B (Blue) on the keyboard to change cannon ammo color.

If PainterFinal compiles and runs via F5, your Visual Studio + MonoGame setup is 100% ready for the semester!
