Part I: C# Program Structure

Chapters 2 & 3 — From Instructions to Namespaces

How C# Translates Your Source Code

Unlike Python (which uses an interpreter), C# uses a two-compiler pipeline:

  1. C# Compiler: Translates your human-readable .cs source files into platform-independent Intermediate Language (IL) stored in an assembly (.dll / .exe).
  2. Just-In-Time (JIT) Compiler: At runtime, the .NET runtime compiles IL instructions into native machine code for your specific CPU (Windows, Linux, or macOS).
  3. Why It Matters: Errors in syntax or data types are caught before your game ever runs!

Syntax vs. Semantics & Development Cycle

Every programmer lives inside the Edit → Compile → Run loop:

  • Syntax (Grammar Rules): Strict C# rules checked by the compiler (e.g., missing semicolons or mismatched braces block compilation).
  • Semantics (Actual Meaning): Whether the compiled program actually behaves the way you intended (e.g., moving left instead of right).
  • Golden Rule: A program that compiles cleanly is syntactically valid, but you must run and test it to verify it is semantically correct.

Hierarchy of a C# Program

C# combines imperative, procedural, and object-oriented paradigms into four nested layers:

  1. Instructions: Individual commands that perform work and change memory; always end with a semicolon (;).
  2. Methods: Named groups of instructions that execute only when called (e.g., Jump();).
  3. Classes: Blueprints that group related methods and data together (e.g., class Character).
  4. Namespaces: Logical folders that group related classes and prevent naming collisions.

Instructions, Methods & Parameters

Recall the line you edited in Chapter 1:

GraphicsDevice.Clear(Color.CornflowerBlue);
  • Instruction: Ends with ;, telling the compiler where one command finishes and the next begins.
  • Method Call: Invokes Clear, a reusable group of rendering instructions defined inside MonoGame.
  • Parameter: The value inside parentheses (Color.CornflowerBlue) passes specific data into the method. Methods without parameters still require empty parentheses: Jump();.

Classes: Blueprints for Game Objects

Just as a method does nothing until called, a class does nothing until you create an instance (object) from it:

  • Class = Blueprint: Defines what data an entity holds and what methods (behaviors) it can perform.
  • Object = Instance: A concrete entity created in memory from that blueprint.
  • Game Example: One Ghost class in Pac-Man serves as the blueprint for four distinct ghost objects (Blinky, Pinky, Inky, Clyde).

Anatomy of the Smallest C# Program

Listing 3.1 demonstrates a complete, runnable C# console program:

class HelloWorld
{
    static void Main()
    {
        System.Console.WriteLine("Hello World!");
        System.Console.Read();
    }
}
  • class HelloWorld: Class header, followed by curly braces { } enclosing the class body.
  • static void Main(): The mandatory entry-point method called automatically when the program starts.
  • Instructions: WriteLine(...) prints text; Read() pauses until a key is pressed.

Namespaces & External Libraries (using)

Large programs organize classes into namespaces to avoid name conflicts:

using Microsoft.Xna.Framework;
using Microsoft.Xna.Framework.Graphics;
using System;

namespace MyFirstGame
{
    class BasicGame : Game
    {
        // Can write "Color" instead of "Microsoft.Xna.Framework.Color"
    }
}
  • namespace: Wraps your classes in a logical group (like folders on disk).
  • using Directive: Imports existing libraries so you don't have to type full namespace prefixes every time.

Structure of a MonoGame Application

Listing 3.2 shows how MonoGame structures a real-time game class:

class BasicGame : Game
{
    GraphicsDeviceManager graphics;

    static void Main()
    {
        BasicGame game = new BasicGame();
        game.Run();
    }

    public BasicGame() { graphics = new GraphicsDeviceManager(this); }
    protected override void LoadContent() { }
    protected override void Update(GameTime gameTime) { }
    protected override void Draw(GameTime gameTime)
    {
        GraphicsDevice.Clear(Color.Olive);
    }
}

Program Layout: Comments & Whitespace

Clean formatting makes code readable for humans while the compiler ignores extra spacing:

  • Single-Line Comment (//): Ignores everything from // to the end of the line. Explain intent, not obvious syntax.
  • Multi-Line Comment (/* ... */): Ignores blocks of text across multiple lines.
  • XML Summary (/// <summary>): Placed above classes/methods to generate IDE documentation tooltips.
  • Whitespace & Indentation: C# ignores extra newlines and spaces outside string literals, but consistent indentation inside { } blocks is essential engineering practice.

Part II: Static Typing & Primitive Data Types

Chapter 4 — Storing and Manipulating Data in Memory

Variables & Static Typing

A variable is a named location in computer memory that stores a value of a specific data type.

  • Static Typing (C#): Every variable's type must be declared explicitly before use, and it cannot change later.
  • Compile-Time Safety: The compiler rejects mismatched assignments before execution (e.g., trying to store Color.Olive inside an int variable).
  • Compare with Python: Python checks types dynamically at runtime; C# enforces type contracts up front for speed and safety.

Declaration, Assignment & Constants

int red;                 // 1. Declaration: reserves memory for an int
red = 3;                 // 2. Assignment ("becomes" 3)
red = 5;                 // Overwrites previous value (now 5)

int age = 16;            // 3. Combined declaration & initialization
int a = 4, b = 15;       // Multiple declarations on one line

const int speedLimit = 100; // 4. Constant: cannot be modified later
// speedLimit = 5000;    // COMPILER ERROR!

Mental Tip: Read = as "becomes" (assignment), not mathematical equality (==).

Expressions vs. Instructions

Understanding how C# builds computations from smaller pieces:

  • Expression: A code fragment that evaluates to a value of a specific type (e.g., 16, age + 12, Color.Olive).
  • Instruction: A complete command ending with ; that performs an action or modifies memory (e.g., int total = age + 12;).
  • Type Matching Rule: The type of the expression on the right of = must match (or safely convert to) the variable type on the left.

Arithmetic Operators & Integer Division

C# supports five standard binary arithmetic operators: +, -, *, /, and % (modulo):

  • Explicit Multiplication: Always write age * 3 (writing age3 refers to a different variable name).
  • Integer Division Truncation: Dividing two int values drops the fractional part (no rounding!):
    • 14 / 3 evaluates to 4
    • 3 / 4 evaluates to 0
  • Modulo Operator (%): Returns the division remainder (e.g., 14 % 3 is 2; 456 % 10 is 6).
  • Precedence & Shorthand: Follows standard PEMDAS rules; supports compound assignments (+=, -=, *=, /=) and unary ++ / --.

Primitive Types vs. Class/Struct Types

C# distinguishes built-in fundamental types from complex object types:

  • Primitive Types: Built directly into the C# language core to store single basic values (integers, floating-point numbers, booleans, characters).
  • Class & Struct Types: Composite types defined by libraries (like MonoGame's Color and GameTime) or by you, grouping multiple sub-values and methods together.
  • Instantiation: Complex types are often created using the new keyword (e.g., Color bg = new Color(255, 0, 0);).

C# Integer Primitive Types (8 Types)

Integer types store whole numbers and differ by memory size (bytes) and signed vs. unsigned range:

Type Size Minimum Value Maximum Value
sbyte / byte 1 byte -128 / 0 127 / 255
short / ushort 2 bytes -32,768 / 0 32,767 / 65,535
int / uint 4 bytes -2,147,483,648 / 0 2,147,483,647 / 4,294,967,295
long / ulong 8 bytes $-9.22 \times 10^{18}$ / 0 $9.22 \times 10^{18}$ / $1.84 \times 10^{19}$

Default Choice: Use int for standard whole numbers unless you need massive ranges (long) or raw byte buffers (byte).

Floating-Point & Real Number Types

C# provides three types for numbers with fractional parts, trading off speed, range, and precision:

Type Size Precision Suffix & Primary Use Case
float 4 bytes ~7 digits 0.3f — Fast 2D/3D game math (MonoGame standard)
double 8 bytes ~15 digits 3.14 (default literal) — General scientific/math calculations
decimal 16 bytes 28 digits 19.99m — Financial & exact base-10 calculations

Text & Logical Types: string, char, bool

Alongside numeric types, games rely heavily on text and true/false flags:

  • string: Represents sequences of text enclosed in double quotes ("Player 1"). Supports concatenation with + (e.g., "Score: " + score), but not arithmetic like *.
  • char: Represents a single Unicode character enclosed in single quotes ('A', '#').
  • bool: Stores logical truth values: strictly true or false (e.g., bool isGameOver = false;).

Mixing Types, Suffixes & Explicit Casting

C# prevents accidental data loss when assigning a wider type into a narrower type:

// Decimal literals default to 'double' in C#:
// float speed = 0.3;        // COMPILER ERROR: double cannot fit in float!
float speed = 0.3f;          // VALID: 'f' suffix marks literal as float

double account = 12345678912345.0;
// float newAccount = account;       // COMPILER ERROR: potential precision loss
float newAccount = (float)account;   // VALID: explicit cast acknowledges precision loss
  • Explicit Cast (targetType)expr: Tells the compiler you intentionally want to convert between compatible numeric types.
  • Unrelated Types: You cannot cast unrelated types (e.g., (float)Color.Red is invalid).
