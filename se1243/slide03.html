Part I: Variable Scope (Local vs. Member Variables)

Chapter 4 (Section 4.4) — Managing Game World State

What Is Variable Scope?

The scope of a variable is the region of code where that variable is visible, valid, and exists in memory.

  • Block Scope Rule: In C#, scope is bounded by the innermost enclosing pair of curly braces { ... } where the variable is declared.
  • Lifetime in Memory: Memory is reserved when execution enters the block and reclaimed once execution exits ("goes out of scope").
  • Why It Matters: Keeps temporary calculations isolated so your program does not waste memory on short-lived helper values.

Local Variables (Method-Level Scope)

A variable declared inside a method is a local variable—accessible only inside that specific method.

protected override void Update(GameTime gameTime)
{
    // Local helper variable: exists ONLY inside Update()
    int redComponent = gameTime.TotalGameTime.Milliseconds / 4;
}

protected override void Draw(GameTime gameTime)
{
    // COMPILER ERROR: 'redComponent' does not exist in Draw()!
    // GraphicsDevice.Clear(new Color(redComponent, 0, 0));
}

Every frame, redComponent is created when Update runs and destroyed as soon as Update finishes.

Member Variables / Fields (Class-Level Scope)

A variable declared inside the class body (outside all methods) is a member variable (officially called a field in C#).

class DiscoWorld : Game
{
    GraphicsDeviceManager graphics;
    Color background; // Member variable: visible to ALL methods in DiscoWorld

    protected override void Update(GameTime gameTime)
    {
        int redComponent = gameTime.TotalGameTime.Milliseconds / 4;
        background = new Color(redComponent, 0, 0); // Updates member variable
    }

    protected override void Draw(GameTime gameTime)
    {
        GraphicsDevice.Clear(background); // Reads the updated member variable
    }
}

Local Variables vs. Member Variables

Aspect Local Variable Member Variable (Field)
Where Declared Inside a method or inner { } block Directly inside a class (outside methods)
Visibility Only within its declaring method/block Accessible across all methods of the class
Lifetime Temporary; destroyed when method returns Persists as long as the class instance exists
Game Role Intermediate calculations (e.g., redComponent) Stores the persistent game world state (e.g., background, score, position)

The Core Game Loop State Pattern

Every MonoGame application you build in SE 1243 follows this exact separation of responsibilities:

  1. Member Variables = Game World: Represent the state of your game (colors, player coordinates, velocities, scores).
  2. Update(GameTime gameTime) = Simulation: Computes changes over time using local helper variables and writes new values into member variables.
  3. Draw(GameTime gameTime) = Rendering: Reads those member variables and renders a visual snapshot to the screen—without mutating game logic.

Watch Out for Shadowing: Writing Color background = new Color(...); inside Update creates a new local variable that hides the member variable!

Part II: Value Types vs. Reference Types

CO2 (LO6) — Stack vs. Heap Memory, Parameter Passing & Null Checks

How .NET Organizes Memory: Stack vs. Heap

When your C# program runs, the .NET runtime divides working memory into two distinct regions:

The Call Stack

  • Fast, fixed-size, Last-In-First-Out (LIFO) memory.
  • Automatically allocates and frees local variables when methods are called and return.
  • Stores Value Types directly and stores memory addresses (references) pointing to the Heap.

The Managed Heap

  • Large, flexible pool of memory for dynamic objects of varying sizes.
  • Allocated via the new keyword; objects persist across method calls.
  • Automatically cleaned up by the Garbage Collector (GC) when no references remain.

Value Types (struct & Primitive Numbers)

A value type variable holds its actual data directly inside its own memory slot.

  • Built-In Primitives: int, float, double, decimal, bool, char, byte, long.
  • Structs (struct): Lightweight custom value types—including MonoGame's Color, Vector2, Point, and Rectangle!
  • Memory Layout: Assigning int b = a; copies the actual numeric bits into a separate, independent variable.
  • Cannot Be Null: A standard value type always contains a concrete value (e.g., 0 or false), never null.

Reference Types (class Instances & string)

A reference type variable does not hold the object itself—it holds a memory address (pointer) to the object on the Heap.

  • All Classes (class): Any type defined with class (e.g., BasicGame, Texture2D, SpriteBatch, Character).
  • Built-In Reference Types: string, arrays (int[]), and collections (List<T>).
  • Two-Part Allocation: Declaring Character hero; reserves space for a reference; new Character() allocates the actual object on the Heap.

Assignment Behavior: Copy vs. Alias

// 1. VALUE TYPE (struct): Independent copies
Vector2 posA = new Vector2(100, 200);
Vector2 posB = posA;      // Copies (100, 200) into posB
posB.X = 500;             // posA.X is STILL 100!

// 2. REFERENCE TYPE (class): Both variables point to the SAME Heap object
Character hero1 = new Character();
hero1.Health = 100;
Character hero2 = hero1;  // Copies the memory address, NOT the object
hero2.Health = 25;        // hero1.Health is NOW 25 too!

Modifying a reference type through one variable affects all variables referencing that same Heap instance.

Passing Value vs. Reference Types to Methods

By default, C# passes method arguments by value—meaning the method receives a copy of whatever is inside the variable:

  • Passing a Value Type (int, Vector2): The method gets a copy of the data. Changing the parameter inside the method does not change the caller's original variable.
  • Passing a Reference Type (Character): The method gets a copy of the Heap address. Both the caller and the method point to the same object, so mutating properties inside the method (e.g., target.Health -= 10;) updates the original object!

null References & Defensive Checks

null is a special literal meaning a reference variable currently points to no object in memory.

Character enemy = null; // Valid for reference types (Invalid for 'int')

// CRASH! Calling a method or property on null throws NullReferenceException:
// enemy.Health = 50;

// Safe defensive null check:
if (enemy != null)
{
    enemy.Health = 50;
}

Common Bug: Declaring a class member variable (Texture2D playerSprite;) and forgetting to load/instantiate it before calling spriteBatch.Draw(playerSprite, ...)!

Summary: Value Types vs. Reference Types

Characteristic Value Type (struct / Primitive) Reference Type (class / string)
Examples int, float, bool, Color, Vector2 Game, SpriteBatch, Texture2D, string
Storage Location Directly on the Stack (or inline inside a parent object) Object on the Heap; reference address on the Stack
Assignment (=) Copies the actual value (independent data) Copies the reference (two aliases to one object)
Allows null? No (defaults to 0 / false) Yes (defaults to null; requires null checks)
Cleanup Instantaneous when scope ends Reclaimed automatically by Garbage Collector (GC)
