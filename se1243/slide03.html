Part I: Variable Scope (Local vs. Member Variables)

Chapter 4 (Section 4.4) — Managing Game World State

What Is Variable Scope?

The scope of a variable is bounded by the innermost enclosing curly braces { ... } where it is declared:

static void Main()
{
    int outerScore = 100; // Visible throughout Main()
    {
        int bonus = 25;   // Visible ONLY inside this inner { } block
        outerScore += bonus;
    }
    // bonus = 50;        // COMPILER ERROR: 'bonus' is out of scope!
    Console.WriteLine(outerScore); // Valid: prints 125
}
  • Lifetime in Memory: Memory is reserved when execution enters { and reclaimed immediately when execution exits }.
  • Why It Matters: Keeps temporary calculations isolated so short-lived values do not clutter class state.

Local Variables (Method-Level Scope)

A variable declared inside a method is a local variable—accessible only inside that specific method.

protected override void Update(GameTime gameTime)
{
    // Local helper variable: exists ONLY inside Update()
    int redComponent = gameTime.TotalGameTime.Milliseconds / 4;
}

protected override void Draw(GameTime gameTime)
{
    // COMPILER ERROR: 'redComponent' does not exist in Draw()!
    // GraphicsDevice.Clear(new Color(redComponent, 0, 0));
}

Every frame, redComponent is created when Update runs and destroyed as soon as Update finishes.

Member Variables / Fields (Class-Level Scope)

A variable declared inside the class body (outside all methods) is a member variable (officially called a field in C#).

class DiscoWorld : Game
{
    GraphicsDeviceManager graphics;
    Color background; // Member variable: visible to ALL methods in DiscoWorld

    protected override void Update(GameTime gameTime)
    {
        int redComponent = gameTime.TotalGameTime.Milliseconds / 4;
        background = new Color(redComponent, 0, 0); // Updates member variable
    }

    protected override void Draw(GameTime gameTime)
    {
        GraphicsDevice.Clear(background); // Reads the updated member variable
    }
}

Local Variables vs. Member Variables

Aspect Local Variable Member Variable (Field)
Where Declared Inside a method or inner { } block Directly inside a class (outside methods)
Visibility Only within its declaring method/block Accessible across all methods of the class
Lifetime Temporary; destroyed when method returns Persists as long as the class instance exists
Game Role Intermediate calculations (e.g., redComponent) Stores the persistent game world state (e.g., background, score, position)

Game Loop State Pattern & Variable Shadowing

Member variables store game state; Update mutates them; Draw renders them. Never re-declare a member variable's type inside a method:

class ScoreBoard
{
    int score = 0; // Member variable (field)

    public void AddPoints(int pts)
    {
        // BUG (Shadowing): Declares a NEW local variable that hides the field!
        // int score = 0;
        // score += pts;

        // CORRECT: Assigns directly to the class member variable
        score += pts;
    }
}

Rule: Use the data type only once when declaring the field at the top of the class.

Part II: Value Types, Reference Types & Essential C# Syntax

CO2 (LO5 & LO6) — Stack vs. Heap, Custom Types, Static Methods & Conditionals

How .NET Organizes Memory: Stack vs. Heap

When your C# program runs, the .NET runtime divides working memory into two distinct regions:

The Call Stack

  • Fast, fixed-size, Last-In-First-Out (LIFO) memory.
  • Automatically allocates and frees local variables when methods are called and return.
  • Stores Value Types directly and stores memory addresses (references) pointing to the Heap.

The Managed Heap

  • Large, flexible pool of memory for dynamic objects of varying sizes.
  • Allocated via the new keyword; objects persist across method calls.
  • Automatically cleaned up by the Garbage Collector (GC) when no references remain.

Value Types (struct) & public Fields

A value type holds its data directly in its own memory slot. In C#, fields default to private—add public so other classes/methods can read or modify them:

struct Position2D
{
    public float X; // Without 'public', Main() gets a compiler error!
    public float Y;
}

// Usage in Main():
Position2D spawnPoint = new Position2D();
spawnPoint.X = 120.5f;
spawnPoint.Y = 300.0f;
  • Examples: Primitives (int, float, bool) and MonoGame structs (Color, Vector2, Point).
  • Cannot Be Null: Value types always contain concrete data, never null.

Reference Types (class) & Heap Allocation

A reference type variable stores a memory address pointing to an object allocated on the Heap via new:

class EnemyUnit
{
    public string Name;  // Reference type field (stored on Heap)
    public int Health;   // Value type field (stored inline inside the Heap object)
}

// Two-step allocation:
EnemyUnit goblin;               // 1. Declares a reference variable on the Stack
goblin = new EnemyUnit();       // 2. Allocates the actual object on the Heap
goblin.Name = "Cave Goblin";
goblin.Health = 80;

Built-In Reference Types: All class types, string, arrays (int[]), and List<T>.

Assignment Behavior: Copy vs. Alias

// 1. VALUE TYPE (struct): Independent copies
Position2D posA = new Position2D();
posA.X = 100;
Position2D posB = posA;   // Copies X=100 into a separate struct
posB.X = 500;             // posA.X is STILL 100!

// 2. REFERENCE TYPE (class): Both variables point to the SAME Heap object
EnemyUnit enemy1 = new EnemyUnit();
enemy1.Health = 100;
EnemyUnit enemy2 = enemy1; // Copies the memory address, NOT the object
enemy2.Health = 25;        // enemy1.Health is NOW 25 too!

Modifying a reference type through one variable affects all variables referencing that same Heap instance.

Parameter Passing & static Helper Methods

Helper methods called directly from static void Main() must also be marked static:

class Program
{
    static void MovePoint(Position2D p)   // Receives a COPY of the struct
    {
        p.X += 50;                        // Modifies local copy only
    }

    static void DamageUnit(EnemyUnit u)   // Receives a COPY of the Heap address
    {
        u.Health -= 20;                   // Mutates the original Heap object!
    }

    static void Main()
    {
        Position2D pt = new Position2D(); pt.X = 10;
        MovePoint(pt);                    // pt.X is STILL 10

        EnemyUnit orc = new EnemyUnit(); orc.Health = 100;
        DamageUnit(orc);                  // orc.Health is NOW 80!
    }
}

Basic if Statements & Defensive null Checks

Unlike Python (if unit is not None:), C# requires parentheses ( ) around the condition and curly braces { } for the body:

EnemyUnit boss = null; // Valid for class references (Compiler error for 'int' or 'struct')

// CRASH: Accessing a field on null throws NullReferenceException:
// Console.WriteLine(boss.Health);

// Safe defensive null check using C# if-else syntax:
if (boss != null)
{
    Console.WriteLine("Boss HP: " + boss.Health);
}
else
{
    Console.WriteLine("No active boss in memory.");
}

C# Syntax Bridge: 3 Rules to Remember

Avoid the top three compiler errors when writing C# console & MonoGame code:

Syntax Rule Common Mistake (Compiler Error) Valid C# Syntax
1. public Fields struct Pt { int X; } (defaults to private) struct Pt { public int X; }
2. static Helpers Calling void Test() from static void Main() Declare static void Test() when called from Main()
3. if ( ) Parentheses if x != null: (Python-style colon) if (x != null) { ... }

Summary: Value Types vs. Reference Types

Characteristic Value Type (struct / Primitive) Reference Type (class / string)
Examples int, float, bool, Color, Vector2 Game, SpriteBatch, Texture2D, string
Storage Location Directly on the Stack (or inline inside a parent object) Object on the Heap; reference address on the Stack
Assignment (=) Copies the actual value (independent data) Copies the reference (two aliases to one object)
Allows null? No (defaults to 0 / false) Yes (defaults to null; requires null checks)
Cleanup Instantaneous when scope ends Reclaimed automatically by Garbage Collector (GC)
