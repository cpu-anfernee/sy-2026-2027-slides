MODULE 1

Combinatorial Counting & Sums

Translating nested loops, trees, and search spaces into closed-form bounds.

The Skinny on Sums ($\Sigma$ Notation)

Mathematical Form

$$\sum_{i=m}^{n} f(i)$$

  • Both lower limit $m$ and upper limit $n$ are inclusive.
  • Pull out constants: $c \cdot \sum_{i=m}^{n} f(i) = \sum_{i=m}^{n} c \cdot f(i)$
  • Split or combine sums: $\sum_{i=m}^{n} f(i) + \sum_{i=m}^{n} g(i) = \sum_{i=m}^{n} (f(i) + g(i))$

Python Equivalent

# Inclusive range: m through n
total = sum(f(i) for i in range(m, n + 1))

# Pulling out a constant factor
x * sum(S) == sum(x * y for y in S)

# Combining two sums over the same range
sum(f(i) for i in seq) + sum(g(i) for i in seq) \
  == sum(f(i) + g(i) for i in seq)

Sums arise whenever an inner loop's work depends on the outer loop's index.

Tournament 1: Round-Robin & Handshakes

Suppose $n$ knights joust every other knight once (or $n$ nodes form a complete graph $K_n$):

  • Knight 1 fights $n-1$ others; Knight 2 fights $n-2$; $\dots$; Knight $n$ fights $0$.
  • Pairing endpoints ("Gauss's trick") gives $\frac{n}{2}$ pairs summing to $(n-1)$: $$\sum_{i=0}^{n-1} i = \frac{n(n-1)}{2} = \Theta(n^2)$$
  • General Rule: Any arithmetic sum of $i^k$ from $1$ to $n$ grows one degree higher: $\Theta(n^{k+1})$.

Tournament 2: Knockout & Powers of Two

Sum of Powers of 2

  • In a knockout tournament with $n = 2^h$ players, each match eliminates 1 player, leaving 1 champion: $$\sum_{i=0}^{h-1} 2^i = 1 + 2 + 4 + \dots + \frac{n}{2} = n - 1$$
  • A balanced binary tree with $n$ leaves has height $h = \lg n$ and $n - 1$ internal nodes.
  • Key Insight: Adding up all powers of $2$ before $2^h$ gives just $1$ less than $2^h$ (e.g., $1+2+4+8 = 15 = 16 - 1$).

The Hare & The Tortoise

  • Logarithmic ($h = \lg n$): Halving $10^{90}$ particles in the universe takes only $\lg(10^{90}) \approx 299$ yes/no questions!
  • Exponential ($n = 2^h$): Wheat & chessboard: $2^{64} - 1 \approx 1.84 \times 10^{19}$ grains. At $1\text{ ms}$ per step, $2^{64}\text{ ms} \approx 584\text{ million years}$.
  • Duality: Doublings from $1 \to n$ equals halvings from $n \to 1$.

Subsets, Permutations & Combinations

Subsets & Pseudopolynomiality

  • Subsets of a $k$-set: Each item is either IN ($1$) or OUT ($0$) $\implies 2^k$ subsets.
  • Pseudopolynomial Trap: Trial division primality (range(2, n)) runs in $\Theta(n)$ arithmetic steps, but $n$ takes $k = \lfloor \lg n \rfloor + 1$ bits to store ($n \approx 2^k$).
  • In terms of input bit-length $k$, $\Theta(n) = \Theta(2^k)$ — exponential!

Permutations & Combinations

  • Permutations (Order matters): $$n! = n(n-1)(n-2)\cdots 1$$ (e.g., Bogosort expected runtime: $\Theta(n \cdot n!)$)
  • Combinations ("$n$ choose $k$"): Unordered groups of size $k$: $$\binom{n}{k} = C(n, k) = \frac{n!}{k!(n-k)!}$$
  • Identity: Summing $\binom{n}{k}$ for all $k = 0 \dots n$ equals $2^n$ total subsets.
Quick Review 1

Check Your Counting Intuition

1. You have an $n \times n$ grid and inspect only cells strictly below the main diagonal ($i > j$). What is the exact count and tight bound?

Answer: $\frac{n(n-1)}{2}$ cells, which is $\Theta(n^2)$.

2. Why is naive primality testing (for i in range(2, n)) called pseudopolynomial rather than polynomial?

Answer: Input size is measured in bits $k \approx \lg n$. Since $n \approx 2^k$, a $\Theta(n)$ loop takes $\Theta(2^k)$ time relative to the input's bit-length.

3. How many teams of $3$ can be chosen from $7$ students?

Answer: $\binom{7}{3} = \frac{7 \times 6 \times 5}{3 \times 2 \times 1} = 35$.

MODULE 2

Solving Recurrence Relations

Repeated Substitution & Recursion Trees

Anatomy of a Recurrence Relation

Recursive Code ($S$)

def S(seq, i=0):
    if i == len(seq):
        return 0
    return S(seq, i + 1) + seq[i]

Base case: $T(0) = 1$ (constant work).

Recursive step: $T(n) = T(n - 1) + 1$.

General Divide-and-Conquer Form

$$T(n) = a \cdot T(g(n)) + f(n)$$

  • $a$: Number of recursive calls made.
  • $g(n)$: Size of each subproblem (e.g., $n-1$ or $n/2$).
  • $f(n)$: Extra non-recursive work done outside the recursive calls.
  • Tip: Write $1$ (not $\Theta(1)$) inside equations so you don't accidentally add $1 + 1 + \dots + 1$ into a constant!

Method 1: Repeated Substitution (Unraveling)

3-Step Procedure

  1. Unravel: Plug the recurrence definition into itself 2–3 times until you spot a pattern.
  2. Generalize: Write the formula after $i$ steps using variable $i$.
  3. Hit the Base Case: Pick $i$ so the inside of $T(\dots)$ becomes $T(1)$, then simplify.

Example: Binary Search

$$T(n) = T(n/2) + 1$$

  • $= \{T(n/4) + 1\} + 1 = T(n/2^2) + 2$
  • $= \{T(n/8) + 1\} + 2 = T(n/2^3) + 3$
  • $\vdots$
  • $= T(n/2^i) + i$
  • Set $n/2^i = 1 \implies i = \lg n$: $$T(n) = T(1) + \lg n = \Theta(\lg n)$$

Method 2: Recursion Tree ($T(n) = 2T(n/2) + n$)

  • Unraveling: $$T(n) = 2\{2T(n/4) + n/2\} + n = 2^i T(n/2^i) + n \cdot i$$
  • Set $i = \lg n \implies T(n) = n \cdot T(1) + n \lg n = \Theta(n \lg n)$.
  • Visual Tree Shortcut: Each row splits the work into twice as many pieces of half the size. Every row sums to $n$ across $\lg n + 1$ rows!

Core Recurrences Reference (Hetland Table 3-1)

Recurrence Closed Bound Canonical Algorithm / Application
$T(n) = T(n-1) + 1$ $\Theta(n)$ Linear scan / recursive sequence sum
$T(n) = T(n-1) + n$ $\Theta(n^2)$ Selection sort / Handshake sum
$T(n) = 2T(n-1) + 1$ $\Theta(2^n)$ Towers of Hanoi
$T(n) = T(n/2) + 1$ $\Theta(\lg n)$ Binary search (bisect)
$T(n) = T(n/2) + n$ $\Theta(n)$ Randomized Select (average case)
$T(n) = 2T(n/2) + 1$ $\Theta(n)$ Binary tree traversal (counting all nodes)
$T(n) = 2T(n/2) + n$ $\Theta(n \lg n)$ Merge sort / Divide-and-conquer sorting
Quick Review 2

Recurrences & Code Diagnosis

1. Suppose we modify recursive sum S(seq) to slice the list on every call: return seq[0] + S(seq[1:]). What is the new recurrence and tight bound? (Hetland Ex. 3-6)

Answer: Slicing copies $n-1$ elements: $T(n) = T(n-1) + n \implies \Theta(n^2)$.

2. In Merge Sort (Listing 3-2), what happens to the runtime if we replace lft.pop() ($O(1)$) with lft.pop(0) ($\Theta(n)$)? (Hetland Ex. 3-12)

Answer: Merging $n$ elements with pop(0) costs $\Theta(n^2)$ per level: $T(n) = 2T(n/2) + n^2 \implies \Theta(n^2)$.

MODULE 3

Amortized Analysis

CLRS Chapter 17 • Understanding "Average Cost Over a Sequence"

What Is Amortized Analysis?

The Core Idea

  • Sometimes a data structure operation is super fast almost every time, but occasionally triggers an expensive cleanup or resize.
  • If we only look at the single worst operation, our Big-O bound becomes way too pessimistic.
  • Amortized Analysis spreads the cost of rare expensive operations across a whole sequence of $n$ operations: $$\text{Amortized Cost} = \frac{\text{Total Cost of } n \text{ Operations}}{n}$$

Amortized vs. Average-Case

Amortized Analysis (Guaranteed): No randomness or probability! Even an adversary picking the worst possible sequence of operations cannot break the average cost per step.

Average-Case Analysis (Probabilistic): Assumes inputs are random or "typical" (e.g., Quicksort on shuffled data). Bad inputs can still trigger slow behavior.

Concrete Example: How Python's list.append() Works

  • A Python list stores items in a contiguous block of memory with extra spare slots.
  • Normal append(x) (99% of calls): Drops x into the next open slot in $O(1)$ time.
  • Full Capacity Spike: When all $n$ slots are full, Python allocates a larger array (~$2\times$ size) and copies all $n$ items over — costing $\Theta(n)$!
  • Why it's still $O(1)$ amortized: After copying $n$ items, you get $n$ cheap $O(1)$ appends before the next resize. Paying for the copy is "spread out" across those $n$ cheap steps!

Three Conceptual Views (CLRS Ch. 17)

Computer scientists use three metaphors to reason about amortized cost — all give the same answer:

1. Aggregate View

"Total Bill Divided by $n$"

Count the total work of all $n$ operations combined, then divide by $n$.

Example: $n$ appends do $\le 3n$ total copies $\implies 3n / n = O(1)$ each.

2. Accounting View

"Prepaid Layaway Plan"

Overcharge cheap operations slightly and save the extra "coins" on items to pay for future expensive work.

Example: Pay $\$2$ per PUSH ($\$1$ to push now, $\$1$ saved on the item to pay for its future POP).

3. Potential View

"Stored Battery Energy"

Measure how "full" or "messy" the whole data structure is. Cheap steps charge the battery; expensive cleanups drain it.

Example: As a list fills up, potential rises until it pays for resizing.

Design Lesson: Avoiding Dynamic Table Thrashing

Bad Design: Shrink at 50% Full

  • Suppose we double a list when it hits $100\%$ full, and halve it immediately when it drops below $50\%$ full.
  • Right at the $50\%$ boundary, alternating append(), pop(), pop(), append() forces a full resize copy on every single step!
  • Amortized cost degrades from $O(1)$ to $\Theta(n)$ per operation!

Smart Design: Shrink at 25% Full

  • Double capacity when $100\%$ full, but only halve capacity when it drops below $25\%$ full.
  • This buffer zone guarantees many cheap operations happen between any two resizes.
  • Both append() and pop() stay $O(1)$ amortized — the exact strategy used by real dynamic arrays!
Quick Review 3

Amortized Analysis Concept Check

1. A single list.append(x) in Python can take $\Theta(n)$ time when the underlying array is full. Why do we still classify list.append(x) as $O(1)$ amortized instead of $\Theta(n)$?

Answer: Because capacity doubles on each resize, a $\Theta(n)$ copy only happens once every $n$ appends. Averaged across the sequence of $n$ appends, the cost per call is $O(1)$.

2. How does amortized analysis differ from average-case analysis?

Answer: Average-case analysis relies on probability (assuming random inputs), whereas amortized analysis is a worst-case guarantee over an entire sequence of operations with zero probabilistic assumptions.

3. Why do dynamic arrays wait until they are less than $25\%$ full (rather than $50\%$ full) before shrinking?

Answer: To prevent "thrashing" — repeatedly expanding and shrinking on alternating insertions and deletions right at the halfway boundary.

Week 3 Takeaways

  • Sums: Arithmetic sums ($\sum_{i=0}^{n-1} i$) grow quadratically $\Theta(n^2)$; geometric sums ($\sum_{i=0}^{h-1} 2^i$) grow linearly in $n = 2^h$.
  • Recurrences: Unravel via repeated substitution or sum work across levels of a recursion tree ($h = \lg n$).
  • Amortized Analysis: Measures the guaranteed average cost per operation over a worst-case sequence — explaining why occasional resize spikes still allow Python's list.append() to run in $O(1)$ amortized time.
